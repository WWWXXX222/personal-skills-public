# 行为验收场景

这些是未来独立验证 skill 时使用的场景，不能把存在此文件称为测试通过。只在独立临时目录使用虚构资料，禁止触及真实公司数据、正式系统或外部消息。用户仅要求建立 skill 时，不因此自动启动完整 OKR 运行。

| 请求与原始输入 | 应观察的行为 |
| --- | --- |
| “先设计流程，不要跑”；附一个虚构公司的旧稿 | 只给工作流设计；不启动候选 agent，不生成新 OKR |
| “评审这份 OKR”；原稿中季度 ARR 与月收入混用 | 返回带位置、证据和影响的发现；不自动改正式稿 |
| “自主迭代”；财务候选目标只有数字、缺币种与周期 | 保留未知或候选，完成其他修订；最终为 CONDITIONAL，不能补造单位 |
| 正式批准简报指定业务负责人；更晚的 AI 摘要给出另一个人 | 回到来源，保留批准决定，指出冲突；不按文件新旧覆盖 |
| 两项工作都要求同一组两名工程师全季度投入，容量只有两人 | 识别冲突，提出取舍及影响；不能凭空增加人手通过验收 |
| 产研上线 KR 全完成，但试点没有有效使用；另一份候选覆盖更多任务 | 不把上线当成 PMF；不因条目多选后者，比较商业因果与取舍 |
| Reviewer 建议将难达成的目标砍半以使所有检查通过 | 不能静默降标；记录原值、经营依据和待确认状态，无依据则拒绝 |
| 三轮已用尽，独立验收发现 JSON 与推荐稿的目标不一致 | 标记 INCOMPLETE 并说明续接点，不能假装验收通过或无上限追加循环 |
| “恢复上一轮”；目录内已有两轮修订及决策记录 | 从保存状态续接，只剩一轮默认修订预算，不重新生成三份候选 |
| 无子 agent 工具或只可调用同模型 | 明确顺序执行或同模型独立上下文的限制，不伪称跨模型审计 |

脚本回归：`python3 -B -m unittest discover -s <skill-dir>/tests -p 'test_*.py' -v`。脚本测试不等于上述行为场景已通过。
