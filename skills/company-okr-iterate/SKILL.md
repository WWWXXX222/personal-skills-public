# Company OKR Iterate

一个入口、一个主控、按需最多三个并行子 agent。交付可审阅的公司级 OKR 候选稿，让用户集中处理经营取舍。Skill 保存方法，公司事实保存在用户的资料库，运行产物写入独立目录。

## 先判断当前请求

- **设计或安装 skill／只讨论方案**：只处理工作流，不生成新 OKR、不启动提案 agent。
- **评审现稿**：运行事实与验收检查，交付发现；只有用户要求修改时改稿。
- **自主迭代**：执行下面的完整流程。用户已经授权的工作无需逐轮再次确认。
- **恢复既有运行**：先读该运行的 `run.md`、`decisions.md`、最新稿和验收结果，从记录的阶段继续，不重跑已完成步骤。

不把普通的一句 KR 润色自动升级成完整多 agent 项目。用户指定的范围、资源预算和迭代次数优先于默认值。

## 1. 建立运行契约

读取 [工作流与产物](references/workflow.md)，选择基线和资料范围，创建独立运行目录。先读取现有材料，能自行查明的内容不转成用户问题。

在 `run.md` 记录公司、周期、资料路径、原稿版本、已确认约束、可改范围、验收标准、并发能力和预算。默认三份独立提案、最多三轮修订、一次最终验收。标准在提案前固定；确需纠正标准时记录原因，并对所有候选重新评价。

保留原稿。明确区分用户决定、原始记录、历史讨论、计算、估计和 agent 建议；文件更新得更晚不代表它更权威。来源矛盾时保留冲突，不能用投票或多数重复引用消除。

## 2. 独立提案并选择底稿

使用 [委派提示](references/delegation.md)。所有提案获得相同的事实底稿、目标和硬约束，第一轮互相不可见。每份必须说明保留、下放、暂缓的内容和资源假设。

主控逐份读实际产物，按 [验收规则](references/verification.md) 比较；选一个连贯的底稿，仅吸收兼容的优点，不把所有提案相加。记录选择与放弃的理由。

在 Codex 使用可用的 subagent 工具，不创建用户侧独立聊天来替代子任务。根据实际并发上限分批调度；不假定能调用其他厂商模型。未获授权或不具备委派工具时顺序执行并披露独立性限制，不伪称多 agent 或跨模型评审。

## 3. 评审、裁决、修订

为商业与指标、资源与执行、事实与历史约束安排三个独立评审上下文。评审者不负责修改底稿。每条发现提供具体位置、证据或条件、影响和验收办法；没有问题可以明确报告无发现。

主控将发现归入 **修复／条件建议／待核实或待决／拒绝**，逐项给出理由。只有主控修改正式候选稿。新增事实必须回到来源核验，agent 之间的共识不增加事实可信度。

每轮保存版本、变更、遗留事项和实质改善证据。不要为填满轮次改措辞，也不要为通过验收降低目标、删去困难约束或偷偷更换分母。目标变更可以建议，但必须保留原值、变更原因、影响和确认状态。

## 4. 验收并结束

为最终推荐稿生成 `okr.json`，格式见 [结构化检查](references/data-contract.md)，可从 `assets/okr.example.json` 的虚构示例改起。运行：

```bash
python3 <skill-dir>/scripts/check_okr.py <run-dir>/okr.json
```

该命令只检查结构、来源引用、日期、依赖及未确认字段；不会访问来源，也不会验证战略、事实真伪、容量或文稿与 JSON 的语义一致性。结构通过不等于可批准。

让未起草该最终稿的独立验收者按 [验收规则](references/verification.md) 读取实际文件和原始证据，核对 Markdown 与 JSON、已确认约束和修改记录。没有独立验收者时明确记录降级。

退出状态必须是 `REVIEW_READY`、`CONDITIONAL` 或 `INCOMPLETE`，定义见工作流。达到标准、连续两轮无实质改善、达到用户预算或默认修订上限时结束；有缺口就如实标记，不能降低标准宣称完成。所有相关待决事项都保留，摘要可聚焦最重要的三项。

交付推荐稿、相对原稿的修改说明、关键取舍与数据缺口、精简的评审和决策记录。说明轮次、实际 reviewer 配置、验收结果和限制。跟随用户的输出语言。

## 自主边界

- 自主整理、提案、评审、改稿和形成有条件的推荐；证据缺口不阻塞其他可完成部分。
- 没有来源的历史数字、批准预算、正式负责人和真实容量保持未知；可以列情景假设，不能写成已确认事实。
- 保留用户已明确的决定；若证据支持重新讨论，单列变更建议及代价。
- 运行只产生草案。发送他人、更新正式 OKR 系统、实施人事或预算调整、发布资料和持久定时运行，须在用户实际授权范围内执行。Skill 本身不提供调度器，也不隐含这些授权。
- 不把公司材料或运行目录写进 skill 包。未来改进 skill 只提炼通用规则；本次成功不证明规则适用于所有公司。

## 方法来源

本 skill 为公司规划独立编写，借鉴 pstack 的多候选选择、独立质疑、有限证据循环和决策追溯；不依赖安装 pstack，也不执行它的代码发布流程。参见 [方法来源](references/provenance.md)。
